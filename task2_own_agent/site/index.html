The Future of Software Engineering

Our working theory: the agents are getting good, the demos are getting shinier, and “works on my machine” has acquired a new coworker.

What we agree on

  • AI tools already help developers write code and find bugs faster, making them useful collaborators in today’s workflow.
  • Generated code still needs careful review; speed does not automatically bring correctness, security, or good judgment along for the ride.
  • As we learn to work with coding agents in the lab, asking clear questions and checking their output matter as much as getting an answer.
  • People will need to keep thinking critically, especially when an answer looks confident enough to skip the tests.

One friendly disagreement

Vaibhav’s prediction: In five to ten years, AI could take a raw idea and turn it into functional software with almost no human intervention.

The cautious counterpoint: “Functional” is doing a heroic amount of work in that sentence. Human oversight may stick around to define what should be built, catch security problems, and notice when the agent has solved the wrong problem beautifully.

Predictions from our tiny crystal ball

  • 2030: Code review includes an agent review—and a human checking what the agent reviewed.
  • 2032: “It passed the tests” is followed by “which tests?” at least once per project.
  • 2035: Turning an idea into software is easier; deciding whether it’s a good idea remains stubbornly human.
